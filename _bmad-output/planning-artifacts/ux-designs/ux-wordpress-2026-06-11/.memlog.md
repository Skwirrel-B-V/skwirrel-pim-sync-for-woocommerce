- (event) Update run 2026-08-27: add the Field mapping tab (Epic 6, FR-18/FR-19) to the spines. The prior run 2026-06-11 is final and owns the settings screen; this extends it, does not replace it.
- (decision) Field mapping is an OVERRIDE LAYER, not configuration. Empty means 'use the default source'. Jos: 'If we keep fields empty it will use the default. Its an override option.' The tab states this once at the top rather than repeating it in every field hint.
- (decision) Replace the four free-text 'ID or code' inputs with an explicit source-then-reference picker. Reason: matching_features() resolves an input as BOTH a feature ID and a feature code (ORed), so a numeric input can match two different features and payload order silently decides which one wins. The operator can never see which they got.
- (decision) A mapping's Source dropdown offers three kinds: Default (no override) | Standard Skwirrel field | Custom class feature. Choosing a kind reveals its reference control. Jos chose this over custom-class-only; it also allows overriding a title with a different standard Skwirrel field.
- (decision) Rework lands NOW, before 3.14.0 ships. The four mapping settings are absent from tags 3.13.0 and 3.13.1, so nothing is stored in the wild and there is zero migration burden. Amend Epic 6 stories/tests rather than add a migration story.
- (decision) Class/feature list is fetched on demand via AJAX from getCustomClasses, cached in a transient, with an explicit Refresh button. Degrades to the current free-text input when the API is unreachable or no custom class collection ID is set. Follows the handle_refresh_statuses precedent (class-skwirrel-wc-sync-admin-settings.php:969).
- (decision) A saved mapping whose feature no longer exists in Skwirrel is KEPT and flagged, never silently dropped or cleared. The select retains it as a marked entry plus a warning at the field; sync keeps its NFR-9 non-destructive fallback. The operator decides whether to repoint or clear.
- (decision) custom_feature_type gates which features are offered: numeric-capable types only for Stock quantity, text-capable types for title/short/long description. An invalid mapping becomes unpickable rather than discovered after a sync.
- (change) custom_collection_id is conditionally required on sync_custom_classes | sync_trade_item_custom_classes | sync_grouped_products (admin-settings.php:341) but NOT on any field mapping. A mapping set with those three off therefore saves cleanly and silently does nothing but a log warning. The picker closes this by making the collection ID a visible precondition of the control.
- (event) Rendered key-screen mock .working/field-mapping-key-states.html covering four states: resting (nothing overridden), override chosen (class then feature), precondition missing (no collection ID), stale reference (feature deleted in Skwirrel). Uses DESIGN.md tokens only, no new colours.
- (decision) Stored mapping value must name its own kind: default | standard_field+field | custom_feature+class+feature. Never one ambiguous string. The screen must render a saved mapping without calling Skwirrel, so a row stays truthful during an API outage.
