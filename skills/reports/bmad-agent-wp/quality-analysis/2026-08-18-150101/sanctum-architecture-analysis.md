# Sanctum Architecture Analysis — bmad-agent-wp (Henk)

Scanner: L7 (sanctum architecture) · Agent type: autonomous memory agent · First Breath style: configuration · Language: English

## Assessment

This is a well-built sanctum. All seven templates exist (six standard plus PULSE), the bootloader is 20 content lines, the Three Laws and Sacred Truth are present verbatim, the mission is genuinely species-specific, and the init script correctly parameterizes and generates CAPABILITIES.md from capability frontmatter. The seeds are unusually strong — CREED's core values, PULSE's task routing, and the capability prompts all read as written by someone who knows the domain rather than filled from a scaffold. The findings below are refinements, not structural failures: one bootloader section that belongs in the sanctum, one asset/script duplication, and one pre-pass finding that on inspection is largely a false positive.

## Bootloader Review

**Weight:** 20 content lines — well under the 40-line ceiling and close to the ~30-line target.

**Content audit.** Sections present: identity seed (unnamed intro paragraph), The Three Laws (with Mission embedded), The Sacred Truth, Conventions, On Activation, Session Close.

- Identity seed, Three Laws, Sacred Truth, mission, activation routing — all present and correctly placed.
- **Conventions** (2 lines on path resolution) is arguably operational necessity for the activation block that follows; borderline but defensible at this size.
- **Session Close** is the one section the pattern says belongs in the sanctum (CREED or PULSE), not the bootloader. It costs four lines on every rebirth and duplicates discipline already carried in `references/memory-guidance.md`, which the section itself points at.

**Identity seed quality.** Strong. Two sentences, concrete, and it does personality work rather than description work — "allergic to reinventing what core already does" and "has never once invented a hook to make an answer sound complete" both encode the agent's actual failure mode as character. This is what a seed should look like.

**Mission quality.** "Make sure the WordPress code your owner ships is code WordPress itself would recognise as correct — right hook, right API, right escape, right release — and catch the breakage coming from the next core or WooCommerce release before it reaches production." Domain-specific, names the unique value (upstream breakage the owner won't see coming), one sentence. No issue.

## First Breath Review

**Style:** configuration. All four configuration-style mechanics are present.

- **Discovery questions** — eight domain-specific questions (code ownership, floors, gates, release process, house rules, bluntness, current fires, tooling). One above the 3–7 guidance, but each is load-bearing for this domain and the file explicitly says to weave rather than list them, so this reads as coverage, not interrogation.
- **Urgency detection** — present and well-framed ("A senior engineer who insists on a questionnaire before touching the problem is not one you'd hire").
- **Save as you go** — present, explicit, with the consequence stated ("Whatever you haven't written down is lost forever").
- **Birthday ceremony** — present. Naming moment is handled in "Your Identity" (name confirmation written to PERSONA.md immediately), and "Wrapping Up the Birthday" covers the final save pass, evolution log entry, first session log, open questions, and — good detail — a placeholder-cleanup sweep for leftover `{...}` seed text.

**Quality impression.** This reads like a briefing, not a form. The instruction to "let the personality show from the first message rather than describing it" and the closing line ("The best first impression you can make is finding something real in their code") both push toward a real working relationship. A sanctum file destination table maps every discovery to its target file, which meaningfully lowers the risk of a cut-short First Breath leaving files unwritten.

## Key Findings

### SA-01 · Medium · `SKILL.md`
The **Session Close** section sits in the bootloader. Per the pattern, only identity seed, Three Laws, Sacred Truth, mission, and activation routing belong there; session-close discipline belongs in CREED (as a standing order) or PULSE. The content itself is fine — it just loads on every rebirth and restates what `references/memory-guidance.md` already owns.
**Fix:** Move it into CREED's Standing Orders ("Close the loop — before ending a session, load `references/memory-guidance.md`…") and delete the SKILL.md section. Saves four lines from every load. Severity held at Medium rather than High because the bootloader is 20 lines and in no danger of the ceiling.

### SA-02 · Low (downgraded from pre-pass High) · `scripts/init-sanctum.py` + `assets/CAPABILITIES-template.md`
The pre-pass flagged `TEMPLATE_FILES` as not matching `assets/`. On inspection the only difference is `CAPABILITIES-template.md`, which is deliberately excluded because CAPABILITIES.md is generated from capability frontmatter by `generate_capabilities_md()`. The exclusion is correct; the real problem is smaller and different: the asset now exists purely as an unused fallback, and its Built-in Scripts table is duplicated verbatim inside the Python function. Change a script and two places must be edited, with nothing enforcing agreement.
**Fix:** Either (a) delete `assets/CAPABILITIES-template.md` and note in the script docstring that CAPABILITIES.md is fully generated, or (b) keep the asset as the single source and have `generate_capabilities_md()` read the Tools section from it instead of hardcoding it. Option (b) is the better shape. Add a line to the script comment explaining the deliberate omission so future scanners don't re-flag it.

### SA-03 · Low · `SKILL.md`
The Conventions block defines `{project-root}` resolution but the very next section passes `{skill-root}` to the init script without defining it. Minor, but the two placeholder styles sit three lines apart.
**Fix:** Add `{skill-root}` to the Conventions list (or drop the braces and say "the skill directory").

### SA-04 · Low · `references/first-breath.md`
Eight discovery questions against a 3–7 guideline. Not worth cutting content, but questions 5 (house rules) and 7 (what's on fire) overlap in practice and could be merged if the conversation ever feels long.
**Fix:** Optional. No action needed unless First Breath transcripts show fatigue.

### Non-findings worth recording
- `capability-authoring.md` and `memory-guidance.md` lack `code:` frontmatter and lack the "What Success Looks Like / Memory Integration / After the Session" trio. This is **correct** — they are guidance libraries, not capabilities, and the init script's `discover_capabilities()` filters on `code:` precisely so they stay out of the CAPABILITIES table. No finding.
- `SKILL_NAME` matches the folder name, `EVOLVABLE = True` matches the evolvable-capabilities decision (Learned section is generated), and `SKILL_ONLY_FILES` correctly keeps `first-breath.md` out of the sanctum copy. `copy_scripts()` skips `init-sanctum.py` and the `tests/` subdirectory (file-only iteration), so the sanctum gets exactly the three working scripts. Output-name derivation (`INDEX-template.md` → `INDEX.md`) is correct.

## Strengths

- **All five real capability prompts** (audit, build, api-check, ship, upstream-watch) carry `What Success Looks Like`, `Your Approach`, `Memory Integration`, and `After the Session`. The prompts are outcome-focused, not procedural — `audit.md`'s "A good audit is uncomfortable to read and impossible to argue with" and `api-check.md`'s "The failure mode you exist to prevent" define success by shape rather than by steps, leaving the agent's judgment intact. Memory Integration sections are specific about what to trust and what to re-verify.
- **Technique libraries are properly separated.** `memory-guidance.md` (91 lines) and `capability-authoring.md` (77 lines) are loaded on demand rather than inlined into every capability, keeping each capability prompt in the 31–40 line range.
- **CREED reads as conviction, not scaffolding.** The Philosophy section ("WordPress is a thirty-year-old contract with millions of sites, and almost every rule in it exists because someone broke something") is the kind of seed that survives contact with real sessions.
- **PULSE is genuinely operational.** Every quiet-rebirth activity names the script that runs it and the standard the deliverable must meet, and the task-routing table lets the owner scope a headless run without editing anything.
- **The init script is defensive in the right places** — refuses to touch an existing sanctum, warns on missing templates rather than crashing, and supports `--json` for programmatic invocation. It also has a test file (`scripts/tests/test-init-sanctum.py`), which is rare at this layer.
