## Recipe learned: regenerating catalogues here
- No local wp-cli. Use the running wp-env container:
  `npx wp-env run cli --env-cwd=wp-content/plugins/skwirrel-pim-sync wp i18n make-pot . languages/skwirrel-pim-sync.pot --slug=skwirrel-pim-sync --domain=skwirrel-pim-sync --exclude=vendor,node_modules,tests`
- `msgmerge --update --backup=none --no-fuzzy-matching <po> <pot>` per locale.
- **polib wraps differently from gettext** (breaks before the space, gettext after). Editing
  .po files with polib reflows the whole file and produces a 3000-line diff. Always run
  `msgcat --width=79 <po> -o <po>` afterwards to restore canonical wrapping.
- **Compile the .mo LAST.** `AdminSettingsRequiredFieldsTest` asserts mo mtime >= po mtime,
  so any post-compile .po touch (msgcat included) fails the suite.

## PIM API facts (read from ./skwirrel source, 2026-08-27)
- The `skwirrel/` folder at the repo root is the **Skwirrel PIM application source itself** (438M),
  not plugin code. It is the authoritative reference for API shapes — better than guessing from
  payloads. Docs live at `skwirrel/app/app/Views/common/docs/v2/api/get_api.php`; the method
  registry is `skwirrel/app/app/Models/WebService/WebApi/WebApiFactory.php`.
- **`getCustomClasses` (v2)** params: `page`, `limit` (1..1000, default 1000), `custom_class_id[]`,
  `custom_class_code[]`, `custom_collection_id[]`, `include_class_collections`,
  `include_feature_translations`, `include_unit_translations`, `include_value_translations`,
  `include_languages[]`. Returns `{custom_classes: [...], page: {...}}`.
- **Class record:** `custom_class_id`, `custom_class_code`, `custom_class_name`, `is_deprecated`,
  plus `_custom_features[]`.
- **Feature record within a class:** `custom_class_feature_id`, `custom_feature_id`,
  `custom_feature_code`, `custom_feature_type`, `custom_unit_id`, `custom_unit_code`,
  `order_number`; `_custom_feature_translations[]` = `{language, custom_feature_description}` when
  `include_feature_translations` + `include_languages` are set. A/M types also carry
  `_custom_values[]`.
  Source: `Models/Exchange/SkwirrelJson/Export/V2/Record/CustomClassRecord.php`.
- `custom_feature_type` being available in the list is what lets the UI refuse a non-numeric
  feature for Stock quantity *before* a sync proves it wrong.
- Sibling methods that also exist and may be useful later: `getCustomFeatures`, `getCustomValues`,
  `getCustomUnits`, `getMetaClassifications`.
- **Existing precedent for "fetch a Skwirrel list into the settings screen":**
  `handle_refresh_statuses()` in `class-skwirrel-wc-sync-admin-settings.php:969` — nonce via
  `check_ajax_referer`, `manage_woocommerce` capability check, paged POST. Follow this shape.

## Roundtable review — story 7.1 (Test Connection scoped probe)

Reviewed `_bmad-output/implementation-artifacts/7-1-test-connection-scoped-probe.md` as the WP engineer. Facts verified this session (all with file:line evidence):

- `JsonRpc_Client::call()` retry loop is `while ($attempt <= $this->retries)` = retries+1 attempts, blocking `usleep(500000 * $attempt)` backoff, **no total elapsed budget** (`class-skwirrel-wc-sync-jsonrpc-client.php:78,111`). Constructor clamps timeout 5..120, retries 0..5 (`:25`).
  → worst case per call = 6 × 120s + 4.5s ≈ 727s. Story 7.1's "cap at 5 selections" = up to ~73 min in one admin-ajax request. A call-count cap is the wrong bound.
- **Precedent to reuse:** `Admin_Settings::fetch_statuses()` (`:1100-1119`) already clamps to `STATUS_SCAN_TIMEOUT = 10` / `STATUS_SCAN_RETRIES = 1` with an explicit comment about "120s × six attempts", plus a `STATUS_SCAN_BUDGET` elapsed-time chunk. That is the house pattern for any admin-triggered HTTP fan-out.
- `test_connection()` takes **no parameters** (`:198`); `extract_product_count()` is `private static` (`:229`), reads `result.page.number_of_items`, numeric-or-null.
- `Service::get_collection_ids()` is **private non-static** (`class-skwirrel-wc-sync-service.php:2504`) — not reachable from Admin_Settings. `normalize_positive_id()` is already duplicated privately in service:1484, purge-handler:1067, upserter:1344. "Never a second parser" is unachievable without a shared helper.
- `resolve_context_ids()` private static `:612`; `get_context_ids()` public static `:646`. Only the latter is usable from outside.
- Result region is a **`<span id="skwirrel-test-result">`** (`class-skwirrel-wc-sync-admin-dashboard.php:1411`), `role=status aria-live=polite aria-atomic=true`, inline beside the button. `<details>`/`<pre>` are flow content — invalid inside a span. Needs to become a `<div>` (and `.skw-test-result` loses its inline `margin-left:12px` grammar).
- Tone CSS is **panel-scoped**, not row-scoped: `.skw-test-result.skw-test-{success,error,warning}` (`assets/dashboard.css:411-427`). Only `warning` carries a glyph + weight; success/error are colour-only *by documented deliberate choice*. A green-row-1 + amber-row-2 panel needs row-scoped tones and two new non-colour affordances.
- Test-connection JS is **inline** via `wp_register_script(handle, false, …)` + `wp_add_inline_script` (`class-skwirrel-wc-sync-admin-settings.php:1771,1809`). No separately cached .js file → the "stale cached script" degradation clause is near-moot.
- `aria-busy` is set true and false **inside the same synchronous `setRes()` call** (`:1888`) — never observable. Any AC leaning on "the aria-busy bracket" is leaning on a no-op.
- Legacy `admin_post` path renders a **WP admin notice** with `.skw-test-metrics` spans (`class-skwirrel-wc-sync-admin-dashboard.php:2424` area) — it never emits `.skw-test-result`/`.skw-test-headline`. Two renderers, one formatter.
- AJAX handler: `check_ajax_referer('skwirrel_test_connection_nonce','_nonce')` + `current_user_can('manage_woocommerce')`, **no** `wp_ajax_nopriv_` registration. Security of the entry point is fine. No `set_time_limit()` anywhere in that file.
- Redaction in `prepare_test_result_payload()` is a naive `strpos($error_message, $auth_token)` containment check — verbatim tokens only.
